## 4. 测试策略

### 4.1 测试类型

| 测试类型   | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 功能测试   | 验证各模块业务逻辑的正确性，包括正向流程和异常流程         |
| UI测试     | 验证页面布局、样式、交互反馈在不同屏幕尺寸下的表现         |
| 接口测试   | 验证前后端API交互的正确性，包括请求参数、响应数据、异常码  |
| 兼容性测试 | 验证在不同浏览器、不同分辨率、不同网络环境下的表现        |
| 回归测试   | 验证已修复问题不再复现，相关功能正常                        |

### 4.2 优先级定义

| 优先级 | 说明                                     |
| ------ | ---------------------------------------- |
| P0     | 核心功能，阻塞性缺陷，必须优先测试       |
| P1     | 重要功能，影响主要业务流程               |
| P2     | 一般功能，影响次要功能或体验             |

## 9. 风险与注意事项

| 风险项               | 影响                               | 应对措施                                       |
| -------------------- | ---------------------------------- | ---------------------------------------------- |
| 扫码功能H5环境限制   | H5浏览器可能无法直接调用摄像头     | 需在真机或App内嵌WebView环境进行测试；验证H5环境下有友好提示 |
| 弱网环境下接口超时   | 用户操作体验下降                   | 验证loading状态和超时提示是否正常             |
| Token过期时机不确定  | 可能在用户操作过程中Token过期      | 验证401拦截机制是否能在任意页面正常触发       |
| 测试数据依赖         | 部分功能需要特定测试数据           | 提前准备测试账号和测试数据                     |
| 本地存储数据冲突     | 指标/产量录入使用本地存储          | 测试多设备/多浏览器环境下本地存储隔离性       |
