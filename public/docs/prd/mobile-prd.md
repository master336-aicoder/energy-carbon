## 1. 概述

### 1.1 项目背景

能碳数智化平台是一个面向企业级客户的能源与碳排放管理系统，PC 端已覆盖从数据采集、监测告警、碳核算到报表分析的完整业务链路。随着现场运维人员、能源管理员、碳排放管理员的移动办公需求日益增长，亟需构建配套的移动端应用，以支持：

- **现场数据快速录入**：抄表、巡检、异常上报等场景下，用户无需回到办公室即可完成任务。
- **关键指标随时查看**：管理层在外出时仍能掌握能耗与碳排的核心 KPI 和告警动态。
- **告警实时响应**：告警信息即时推送，支持移动端查看详情、确认和处理，缩短响应周期。

### 1.2 设计目标

| 目标编号 | 目标描述 | 验收标准 |
|---------|---------|---------|
| G1 | **轻量化** | 移动端仅保留高频、核心、适合小屏场景的功能，避免 PC 端功能平移 |
| G2 | **高效录入** | 现场抄表、巡检等录入类操作，单条记录完成时间 <= 30 秒 |
| G3 | **即时触达** | 告警推送到达率 >= 99%，从触发到推送延迟 <= 5 秒 |
| G4 | **离线可用** | 核心录入功能在无网络环境下可正常使用，网络恢复后自动同步 |
| G5 | **多端一致** | 与 PC 端共用一套账号权限体系，数据实时互通 |

### 1.3 技术方案建议

- **前端框架**：UniApp（Vue 3）+ uView UI，一套代码编译到 iOS、Android、微信小程序。
- **状态管理**：Pinia。
- **本地存储**：uni.setStorage（离线缓存）、SQLite（大量离线数据）。
- **推送服务**：集成极光推送 / 个推（App 端）+ 微信订阅消息（小程序端）。
- **扫码能力**：uni.scanCode（调用摄像头识别二维码/条形码）。
- **地图定位**：uni.getLocation + 高德/腾讯地图 SDK。

## 2. 用户画像

### 2.1 用户角色定义

| 角色 | 职责描述 | 典型使用场景 | 使用频率 |
|-----|---------|------------|---------|
| **现场抄表员** | 负责定期到各计量点抄写表码 | 现场扫码/手动录入表码、拍照留证 | 每日多次 |
| **设备巡检员** | 负责用能设备的日常巡检与异常上报 | 扫码查看设备信息、记录巡检结果、上报故障 | 每日多次 |
| **能源管理员** | 负责能耗数据监控、告警处理、报表查看 | 查看实时能耗、处理告警、审批抄表数据 | 每日 |
| **碳排放管理员** | 负责碳排放数据采集与核算支撑 | 录入活动水平数据、查看碳排指标 | 每周多次 |
| **企业管理层** | 关注整体能碳指标与减排进度 | 查看数据看板、接收重要告警 | 每周 |

### 2.2 用户旅程地图（以抄表员为例）

```
出发前 --> 到达计量点 --> 扫码/选择器具 --> 录入表码 --> 拍照 --> 提交 --> 前往下一点
  ↑                                              ↓
  └──────── 查看今日任务清单 / 路线规划 ──────────┘
```

### 2.3 痛点与期望

| 痛点 | 期望的移动端解决方案 |
|-----|------------------|
| 携带纸质抄表本，易丢失、难追溯 | 手机扫码录入，数据实时上传 |
| 现场网络信号差，无法打开 PC 端页面 | 离线缓存，断网也能录，有网自动同步 |
| 告警发生时人在现场，无法及时获知 | 推送通知 + 铃声提醒，一键跳转处理 |
| 设备信息记不住，巡检标准不统一 | 扫码即出设备档案 + 巡检清单 |
| 历史数据查询需回办公室开电脑 | 手机随时查趋势、查记录 |

| | 成本报表 | 适配（只读） | P2 | 查看成本概览 |
| | 节能量报表 | 不适配 | -- | 保留 PC 端 |
| | 汇总报表 | 不适配 | -- | 保留 PC 端 |
| **能效对标** | 能效对标 | 不适配 | -- | 复杂对标分析，保留 PC 端 |
| | 能源流向 | 不适配 | -- | Sankey 大图，保留 PC 端 |
| **双碳管理** | AI 智慧平台 | 不适配 | -- | 大屏展示，保留 PC 端 |
| **工具箱** | AI 报告生成 | 不适配 | -- | 长文本输入，保留 PC 端 |
| | 分时电价 | 适配 | P3 | 查看当日/明日电价时段 |
| | AI 知识库 | 适配 | P2 | 智能问答，支持语音输入 |
| **系统管理** | 设备管理 | 适配（简化版） | P1 | 查看设备列表、扫码添加 |
| | 计量器具 | 适配（简化版） | P1 | 查看器具列表、扫码识别 |
| | 用能单元 | 不适配 | -- | 组织架构维护，保留 PC 端 |
| | 角色/用户/菜单 | 不适配 | -- | 后台管理，保留 PC 端 |
| | **个人中心** | **核心适配** | **P0** | 个人信息、消息通知、设置 |

### 3.2 适配原则总结

1. **核心录入类**：抄表、巡检、碳排放活动数据录入 → **必须适配，体验优先**
2. **告警响应类**：告警查看、确认、处理 → **必须适配，实时优先**
3. **指标查看类**：实时数据、能耗统计、报表 → **简化适配，只读为主**
4. **复杂分析类**：同比环比、能效对标、能源流向、CBAM → **不适配，保留 PC 端**
5. **系统配置类**：角色、用户、菜单、规则配置 → **不适配，保留 PC 端**

### 5.2 底部导航栏（Tab Bar）

采用 **4 Tab** 结构，平衡功能入口深度与操作效率：

| Tab | 名称 | 图标 | 默认页面 | 说明 |
|-----|------|------|---------|------|
| 1 | 首页 | `home` | 数据看板 | 核心 KPI、快捷入口、待办提醒 |
| 2 | 工作 | `briefcase` | 抄表录入 | 高频工作场景入口（抄表/巡检/告警） |
| 3 | 数据 | `chart-line` | 实时数据 | 数据查询与分析相关功能 |
| 4 | 我的 | `user` | 个人中心 | 个人相关、消息、设置 |

**设计说明**：
- "工作" Tab 作为高频操作聚合页，进入后通过顶部 Segmented Control 切换"抄表 / 巡检 / 告警"。
- "数据" Tab 聚合所有只读查询类功能，避免首页信息过载。

```

    └── 告警处理页（L2）

工作（L0）
├── 抄表录入（L1）
│   ├── 扫码/选择器具（L2）
```

## 7. 移动端特有功能

### 7.1 扫码识别

**功能描述**：通过扫描设备或计量器具上的二维码，快速识别对象并进入对应操作页面。

**技术实现**：
- 调用 `uni.scanCode({ scanType: ['qrCode'] })` 打开扫码界面。
- 二维码内容格式建议：`seatone://meter/{meterId}` 或 `seatone://device/{deviceId}`。
- 扫码成功后解析 ID，调用对应 API 获取详情。

**应用场景**：
| 场景 | 扫码后行为 |
|-----|-----------|
| 抄表录入 | 跳转表码录入页，自动填充器具信息 |
| 设备巡检 | 跳转巡检录入页，展示设备档案和巡检清单 |
| 实时数据查看 | 跳转该监测点的实时数据详情页 |
| 设备新增 | 扫码后自动填充设备编码 |

**二维码生成规范**（PC 端/后台需提供）：
- 尺寸：不小于 2cm x 2cm
- 内容：`https://ec.seatone.com/q?type=meter&id=M2024001`（兼容 URL 格式，App 内通过 URL Scheme 拦截）
- 容错级别：H（30%）

### 7.2 离线缓存

**功能描述**：在无网络或弱网环境下，核心录入类操作（抄表、巡检）可正常使用，数据本地缓存，网络恢复后自动同步。

**技术方案**：
- 本地存储：SQLite（大量结构化数据）+ uni.setStorage（配置类数据）。
- 数据表设计：

```sql
-- 离线抄表记录表
CREATE TABLE offline_meter_record (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    local_id TEXT UNIQUE NOT NULL,       -- 本地唯一标识 UUID
    meter_id TEXT NOT NULL,
    record_time TEXT NOT NULL,
    start_code REAL,
    end_code REAL NOT NULL,
    consumption REAL,
    unit_price REAL,
    cost REAL,
    operator TEXT,
    remark TEXT,
    photos TEXT,                          -- JSON 数组，本地图片路径
    sync_status INTEGER DEFAULT 0,        -- 0:待同步 1:同步中 2:成功 3:失败
    sync_fail_reason TEXT,
    create_time TEXT DEFAULT CURRENT_TIMESTAMP
);

-- 离线巡检记录表
CREATE TABLE offline_inspect_record (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    local_id TEXT UNIQUE NOT NULL,
    device_id TEXT NOT NULL,
    inspect_time TEXT NOT NULL,
    result TEXT NOT NULL,                 -- JSON 数组，巡检项结果
    abnormal_count INTEGER DEFAULT 0,
    abnormal_detail TEXT,                 -- JSON
    photos TEXT,
    sync_status INTEGER DEFAULT 0,
    sync_fail_reason TEXT,
    create_time TEXT DEFAULT CURRENT_TIMESTAMP
);
```

**同步策略**：
| 触发条件 | 行为 |
|---------|------|
| 网络恢复（WiFi/4G/5G 连接） | 自动检测并启动同步 |
| App 从后台切换到前台 | 检测网络，如有待同步数据则自动同步 |
| 用户手动点击【全部同步】 | 立即启动同步 |
| 单条数据操作后 | 尝试立即同步该条数据，失败则标记待同步 |

**同步逻辑**：
1. 查询所有 `sync_status = 0` 的记录。
2. 更新状态为 `sync_status = 1`（同步中）。
3. 批量上传至服务端（建议每批次不超过 50 条）。
4. 服务端返回成功 ID 列表，本地标记为 `sync_status = 2`。
5. 失败记录标记为 `sync_status = 3`，记录失败原因，用户可单条重试。

### 7.3 推送通知

**功能描述**：通过系统级推送，将告警、任务提醒等信息即时送达用户。

**推送通道**：
| 平台 | 通道 | 适用场景 |
|-----|------|---------|
| iOS | APNs | 告警通知、任务提醒 |
| Android | 极光推送 / 个推 | 告警通知、任务提醒 |
| 微信小程序 | 微信订阅消息 | 告警通知（需用户订阅） |

**推送内容规范**：

| 场景 | 推送标题 | 推送内容 | 跳转页面 |
|-----|---------|---------|---------|
| 告警触发 | 严重告警：温度超限 | 空压站排气温度达到120℃，超过阈值100℃ | 告警处理页 |
| 抄表任务 | 今日抄表任务提醒 | 您有5项抄表任务待完成，已完成2项 | 抄表录入页 |
| 巡检任务 | 巡检任务分配 | 您有新的巡检任务：空压站区域 | 设备巡检页 |
| 数据同步 | 离线数据同步完成 | 5条记录已成功同步至服务器 | 离线管理页 |
| 系统公告 | 系统维护通知 | 平台将于今晚22:00-24:00进行维护 | 消息详情页 |

**推送频率控制**：
- 同一告警 5 分钟内不重复推送。
- 每日抄表任务提醒仅推送一次（上午 8:00）。
- 用户可在【设置】中关闭非紧急推送。

### 7.4 拍照上传

**功能描述**：在抄表、巡检异常上报等场景，支持拍摄照片并上传，作为数据佐证。

**技术实现**：
- 调用 `uni.chooseImage({ count: 3, sizeType: ['compressed'], sourceType: ['camera'] })`。
- 图片压缩：上传前压缩至宽度 1080px，质量 80%，单张控制在 500KB 以内。
- 存储：先上传至 OSS/COS，返回 URL 后随业务数据提交。

**业务规则**：
| 场景 | 最大张数 | 是否必选 | 用途 |
|-----|---------|---------|------|
| 抄表录入 | 3 | 否 | 表盘照片留证 |
| 巡检异常上报 | 3 | 是 | 异常现场拍照 |
| 设备档案维护 | 5 | 否 | 设备铭牌、现场照片 |

### 7.5 GPS 定位

**功能描述**：在巡检场景中记录巡检人员的位置信息，用于轨迹追溯和区域校验。

**技术实现**：
- 调用 `uni.getLocation({ type: 'gcj02', accuracy: 'best' })`。
- 巡检提交时附带经纬度信息。

**业务规则**：
- 定位精度要求：<= 50 米。
- 定位失败时允许手动提交，但标记为"定位缺失"。
- 巡检点与设备绑定坐标，偏离超过 100 米时提示"您当前位置距离巡检点较远，请确认"。

### 7.6 生物识别登录

**功能描述**：支持指纹/面容识别快速登录，减少密码输入。

**技术实现**：
- 调用 `uni.checkIsSupportSoterAuthentication` 检测支持情况。
- 首次登录成功后，询问是否开启生物识别。
- 后续启动 App 时，优先唤起生物识别，失败时回退到密码登录。

### 7.7 语音输入

**功能描述**：在 AI 知识问答、备注填写等文本输入场景，支持语音转文字。

**技术实现**：
- 调用 `uni.getRecorderManager()` 录制音频。
- 音频上传至服务端调用语音识别 API（阿里云/科大讯飞）。
- 返回文本填充至输入框。
